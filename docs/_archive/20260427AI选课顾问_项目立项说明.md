## 一、产品问题定义

**阶段一结论：通过 — 问题真实存在，目标用户明确**

### 核心问题

大学生在选课时严重缺乏系统性指导：

- 不了解本校成绩规则（绩点算法、各科权重、补考/重修政策）
- 不清楚哪些课程高分省力
- 无法模拟不同选课组合对累积绩点的影响
- 全靠学长学姐口口相传，信息严重不对称

### 目标用户

**有绩点诉求的大学生**，具体为：

- 准备保研的学生
- 申请奖学金的学生
- 计划海外留学申请的学生

### 痛点量级

| 数据维度 | 规模 |
|---------|------|
| 全球在校大学生（UNESCO） | 2.64亿 |
| 中国在校大学生人数 | 约4000万 |
| 绩点影响范围 | 保研 / 奖学金 / 海外留学申请 |

## 三、方案设计

**阶段三结论：通过 — 技术可行，路径清晰**

### MVP 核心功能（预计独立开发 4-6 周）

#### 功能一 — 政策解析器
上传学校课程手册 PDF → AI 提取评分规则、绩点算法、科目权重、补考政策

#### 功能二 — 选课推荐器
输入意向课程 → AI 按「高分潜力 / 工作量」比例排序，推荐最优选课组合

#### 功能三 — GPA 模拟器
模拟不同选课方案 → 预测各场景下的学期绩点与累积绩点变化

### 技术栈

```
前端：Next.js
AI 能力：Claude 3 / GPT-4 API
检索增强：RAG 向量检索
文档处理：PDF 解析
```

**开发周期**：4-6 周（独立开发）
**API 费用**：约 $50-200/月（小规模阶段）
**现金投入**：约为零（个人时间 + API 费用）

### 产品路径选择

| 路径 | 描述 | 优先级 |
|------|------|--------|
| **路径A（推荐）**：Web 应用 | 用户上传本校政策PDF，AI解析存入向量库，验证核心假设最简路径 | 立即执行 |
| 路径B：浏览器插件 | 实时集成学校选课系统，体验更好但复杂度更高 | 路径A验证后再开发 |
| 路径C：移动端 App | 覆盖更广，开发成本更高 | 验证完成后再考虑 |

### RICE 优先级评分

| 维度 | 数值 |
|------|------|
| R（覆盖人数） | 第一年目标10万学生 |
| I（影响程度） | 4/5（高痛点，频繁使用） |
| C（确信度） | 65%（尚未实际验证） |
| E（投入成本） | 6周 |
| **综合得分** | **(10万 × 4 × 0.65) / 6 ≈ 43,333（高优先级）** |

## 四、用户需求分析

### 核心用户场景

1. **选课前** — 用户上传本校手册，查询绩点算法和各课程权重规则
2. **比较课程** — 输入备选课程，获得 AI 推荐的高分/低负担最优组合
3. **模拟推演** — 假设不同方案，预测学期末和累积绩点变化
4. **政策查询** — 快速查找补考、重修、缓考等具体政策细节

### 信息不对称的本质

```
现状：学生 ← 口口相传（学长学姐）← 不完整/不准确/滞后
目标：学生 ← AI直接解析官方政策 ← 准确/即时/覆盖全校
```

## 五、完整网页功能架构

```
AI 选课顾问 Web App
│
├── 1. 用户注册/登录
│   └── 邮箱注册 + 第三方登录
│
├── 2. 学校政策上传与解析

│   ├── AI 提取：绩点算法 / 科目权重 / 补考规则
│   └── 结构化存储（向量数据库）
│
├── 3. 选课推荐
│   ├── 输入意向课程列表

│
├── 4. GPA 模拟器
│   ├── 选定课程组合
│   ├── 模拟不同成绩场景
│   └── 预测学期绩点 & 累积绩点变化
│
├── 5. 政策问答（RAG 检索）
│   ├── 自然语言提问（如「补考几次后强制重修？」）
│   └── AI 基于本校政策精准回答
│
├── 6. 用户中心
│   ├── 已上传的学校政策管理
│   ├── 历史模拟记录
│   └── 订阅状态管理
│
└── 7. 管理后台
    ├── 服务器健康监控（CPU/内存/流量）
    ├── 错误监控（Sentry）
    └── 用户数据统计
```

**商业模式（免费增值）**：
- 免费：上传1所学校政策，基础查询

## 六、AI 能力

### 核心 AI 能力模块

| 能力 | 技术实现 | 用途 |
|------|---------|------|
| PDF 文档解析 | Claude 3 / GPT-4 + PDF parser | 提取学校政策结构化信息 |
| RAG 检索增强 | 向量数据库 + 语义检索 | 保证政策信息准确性，避免幻觉 |
| 课程排序推荐 | LLM + 自定义评分逻辑 | 高分潜力 vs 工作量权衡计算 |
| GPA 模拟预测 | 规则引擎 + AI 辅助 | 多场景绩点预测 |
| 自然语言问答 | RAG + LLM 对话 | 政策细节精准问答 |

### 技术挑战与对策

| 挑战 | 对策 |
|------|------|
| PDF 格式混乱、非标准排版 | 先测试10所学校，建立人工审核流程 |
| 政策信息准确性 | RAG 检索 + 溯源标注（数据来源：XX学校官方教务系统）|
| API 成本随规模增长 | Prompt 缓存 + 免费版使用量限制逻辑 |

## 八、风险评估

**阶段五结论：通过 — 风险可控，止损清晰**

### 风险矩阵

| 风险 | 应对策略 |
|------|---------|
| 学校政策文件频繁更新 | 用户众包更新政策，版本追踪机制 |
| 学校官方限制或舆论压力 | 定位为学业规划工具，避免刷分措辞 |
| PDF 解析准确率不理想 | 先测试10所学校，建立人工审核流程 |
| 选课季节性强，留存率低 | 每学期选课季推送提醒（每年2次） |
| 规模扩大后 API 成本超收入 | Prompt 缓存 + 免费版使用量限制 |
| 学校系统数据爬取风险 | 严格禁止，MVP 阶段只处理用户主动上传的公开信息 |

### 止损条件

> 若 PDF 解析准确率 < 70%，**或**上线3个月内活跃用户 < 100 → 停止并复盘转向
